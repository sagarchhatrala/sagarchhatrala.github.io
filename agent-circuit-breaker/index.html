KNOW THE BOUNDARY

Clear answers.
Clear expectations.

What does UNKNOWN mean?

ACB could not establish that the action passed its supported checks. It is a separate result, not permission. RuntimeGate does not issue executable authority for an unknown action. ALLOW, BLOCK, UNKNOWN, PENDING_APPROVAL, and ERROR remain distinct outcomes.

Does ACB sandbox an entire agent?

No. ACB controls the paths that a trusted integration routes through it. Direct subprocess calls, arbitrary host processes, and compromised trusted executors remain outside that boundary. Use separate OS and network controls where your threat model requires them.

What is the supported deployment scope?

Version 1.7.0 is classified as beta. Its strongest supported path is a single-host trusted RuntimeGate deployment, with workers sharing a local SQLite store and private keys held outside model-visible state. The readiness command checks local store and audit posture; it is not a certification of your application. Distributed coordination and exactly-once external effects are outside scope.

How do the MCP server and legacy proxy differ?

The v1.7.0 stdio workflow server executes typed tools through RuntimeGate with exact approvals and durable start/outcome tracking. The legacy proxy inspects calls before forwarding and does not own that execution lifecycle. Its HTTP mode is a custom JSON POST bridge, not full Streamable HTTP. See the adapter enforcement matrix for each entry point.

Can I inspect the implementation and this demo’s evidence?

Yes. ACB is MIT-licensed. The interactive policy checks and approval walkthrough were freshly recorded from source commit d6dd545.
