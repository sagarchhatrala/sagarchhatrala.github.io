KNOW THE BOUNDARY

Clear answers.
Clear expectations.

What does UNKNOWN mean?

ACB could not establish that the action passed its supported checks. It is a separate result, not permission. RuntimeGate does not issue executable authority for an unknown action. ALLOW, BLOCK, UNKNOWN, PENDING_APPROVAL, and ERROR remain distinct outcomes.

Does ACB sandbox an entire agent?

No. ACB controls the paths that a trusted integration routes through it. Direct subprocess calls, arbitrary host processes, and compromised trusted executors remain outside that boundary. Use separate OS and network controls where your threat model requires them.

What is the supported deployment scope?

Version 1.6.9 is classified as beta. Its strongest supported path is a single-host trusted RuntimeGate deployment, with workers sharing a local SQLite store and private keys held outside model-visible state. The readiness command checks local store and audit posture; it is not a certification of your application. Distributed coordination and exactly-once external effects are outside scope.

Does the MCP proxy provide every runtime guarantee?

No. The proxy can stop forwarding unsafe or unknown calls according to policy, but it does not provide RuntimeGate’s exact approval consumption, suspension and revocation, or durable start/outcome tracking. See the adapter enforcement matrix for each entry point.

Can I inspect the implementation and this demo’s evidence?

Yes. ACB is MIT-licensed. The examples on this page were recorded from source commit 55b9646. Read the recorded results, structured project facts, or plain-text guide. The browser replays results and never runs the Python engine.
