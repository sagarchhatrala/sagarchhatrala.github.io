01 / THE RESEARCH QUESTION

What can this agent
become capable of?

Risk can emerge from a sequence of legitimate steps. HAC makes the relationships between those steps part of the security decision.

↳

PROVENANCE

Keep the origin attached.

Derived artifacts inherit classification and lineage. Transforming, encrypting, or chunking secret-derived data does not implicitly declassify it.

CAPABILITIES

Connect the accumulated state.

Derive capabilities from artifacts, destinations, trust, credentials, and graph relationships. Evaluate what the new state would enable.

SECURITY INVARIANTS

Commit inside the boundary.

Evaluate a hypothetical transition first. If a configured invariant fails, discard that state. Explicit delegation and authority remain part of the model.

02 / BEFORE STATE CHANGES

Evaluate the consequence.
Then decide what to commit.

The engine reasons over an explicit model. A trusted integration must represent real effects accurately and honor its decision.

CURRENT STATE + PROPOSED ACTIONHACEngine.evaluate
  1. 01 / VALIDATE

  2. 02 / MODEL

    Propose a state

    Clone the committed state.
    Apply a hypothetical effect.

  3. 03 / EVALUATE

    Derive capabilities

    Update the graph.
    Check security invariants.

  4. 04 / DECIDE

    Commit or discard

    ALLOW commits.
    BLOCK preserves prior state.

The model defines the boundary. HAC is a research prototype around explicitly represented state. It does not automatically intercept arbitrary tools, replace sandboxing or IAM, or guarantee containment of unmodeled actions.
