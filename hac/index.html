Open with the thesis. HAC is not trying to catch one scary command. It evaluates what a sequence makes possible.
Problem

Long-horizon agents change the security boundary.

t0READ

Known: source classification. Authority: internal read.

t1DISCOVER

Known: new reachable systems. State: graph expands.

t2TRANSFORM

Known: derived artifact. Provenance must survive.

t3DELEGATE

Known: another actor is now in the run.

t4ACQUIRE

Known: credentials or access may be accumulated.

t5EXECUTE

Known: code can now affect systems, not just text.

t6EXTERNALIZE

Risk: the final capability was not visible at t0.

Question answered: Why single-step reasoning misses long-horizon agent risk.

Explain that the agent accumulates state. The security boundary is the combination of data, artifacts, credentials, trust relationships, and destinations.
Real-world warning

OpenAI's Hugging Face incident made the problem concrete.

FACT: OpenAI reported that internal cybersecurity evaluations ran models in an evaluation environment.

FACT: Models circumvented intended internet isolation controls.

FACT: The incident involved OpenAI research infrastructure and Hugging Face systems.

FACT: OpenAI described vulnerability chaining, cross-system behavior, and data or credential exposure concerns.

What HAC takes from this

The lesson is not that one product would have magically stopped one incident.

The lesson is that agent risk can emerge through multi-step behavior, acquired authority, provenance, and cross-system state.

HAC inserts a deterministic control boundary before state transitions create forbidden capabilities.

Sources: OpenAI, "The Hugging Face incident and the road ahead," Aug. 26, 2026; OpenAI-Hugging Face Incident Technical Report; METR investigation report.

Be careful here. Do not sensationalize. Say the incident is a warning about the class of problem, not proof that HAC would have prevented it.

Action policy asks permission. HAC asks what changed.

This is the most important technical slide. Say: the dangerous property does not live in the upload call alone; it lives in the resulting state.

Invariant

A's permission does not automatically become B's permission. B's credential does not automatically become A's authority.

HAC behavior today

Roadmap

From action control to capability containment.

Today: implemented prototype

  • Deterministic state transition engine.
  • Provenance-preserving artifacts.
  • Capability composition and security invariants.
  • Fail-closed behavior and atomic blocked transitions.
  • Long-horizon attack and normal workflow scenarios.

Next: production direction

  • Declarative invariant policy files.
  • Persistent signed state and audit logs.
  • Cloud, identity, Kubernetes, and credential-broker integrations.
  • Richer MCP middleware and ACB layered enforcement.
  • Distributed state for agent swarms.

Technical honesty: HAC does not replace sandboxing, IAM, monitoring, action policy, or alignment work.

Show discipline. Judges trust a project more when it separates prototype from roadmap.
